# Decision: POST /auth/logout clears the cookie

**Date:** 2026-11-03
**Status:** Accepted

## Context
The session cookie is httpOnly, so JavaScript cannot remove it. The locked endpoint list had no logout route; it was added at Gate 1.

## Decision
Add `POST /auth/logout`. It is anonymous and idempotent, returns 204, and sends a `Set-Cookie` that clears `access_token` with the same Path, SameSite, HttpOnly and Secure attributes and Max-Age 0. The web logout button posts to `/api/auth/logout` and navigates to `/signin`.

## Alternatives Considered
### Option A - GET /auth/logout
**Rejected because:** any image tag or link on another site could log the user out.

### Option B - Next.js route handler deletes the cookie
**Rejected because:** issuing and clearing the cookie would live in two apps with two copies of its attributes.

### Option C - Guarded logout (requires a valid token)
**Rejected because:** a user with an expired cookie would get 401 and keep a stale cookie.

## Consequences
- Logout does not revoke the token; a copied token stays valid until expiry (see session ADR).
- 12-18 months: with refresh tokens or server sessions, logout gains a revocation step behind the same route.
- Could go wrong: attribute mismatch leaves the cookie in place (covered by an attribute-equality test).

**Reversibility:** Easy. One route.
